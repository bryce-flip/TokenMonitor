<objective>
**As a** stablecoin operator, **I want to** ingest and inspect correctly classified, real USDT and USDC supply-changing logs in ClickHouse, **so that** I can trust the event data underlying later supply and issuance figures.

This plan builds the walking skeleton: one bounded command that loads operator config (CHAIN-01), fail-fast probes the provider (D-02), fetches bounded filtered eth_getLogs per token, classifies USDT Issue/Redeem/DestroyedBlackFunds and USDC zero-address Transfer events (EVENT-01, EVENT-02), and stores exact raw amounts with full chain provenance in ClickHouse (EVENT-03). Decode correctness is proven offline against the five pinned Mainnet fixtures from research; storage exactness is proven by a ClickHouse integration test.

Purpose: prove the full config -> RPC -> decode -> ClickHouse -> SQL-inspection path on real stack choices before later phases add durability and reconciliation.
Output: a runnable cmd/indexer bounded-ingest command, its config file, the stablecoin_events schema, and offline plus ClickHouse-integration tests.
</objective>

<assumptions>
Explicit unresolved-edge disclosures (no silent drops):

- **Interrupted or parallel runs (CHAIN-01 concurrency probe):** Phase 1 is a one-shot bounded command with no checkpoint. An interrupted run may leave partial rows; re-running the same range re-inserts the same identities and ReplacingMergeTree + FINAL reads collapse them to one logical row each (proven by the replay test in Task 2). Durable checkpoint/atomicity guarantees are Phase 2 (SYNC-02/SYNC-03).
- **Zero-amount events:** a supply event with raw amount 0 is stored as-is; Phase 1 applies no threshold or filtering (thresholds arrive with METR-03 in Phase 4).
- **Config format (Claude's discretion per CONTEXT.md):** the source spec proposes YAML, but research found the simpler stdlib-only path — encoding/json plus os.Getenv (01-RESEARCH.md, "Don't Hand-Roll"). This plan uses config/tokens.json; no YAML dependency is added.
</assumptions>
